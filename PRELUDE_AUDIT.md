# PRELUDE_AUDIT — never ship a stale prelude image again (Phase-5AG)

## 1. The defect class this closes

`tools/build_split.sh` does not compile the runtime that `nnktool` emits today.
It compiles a **frozen dispatch image** — `work/phase3a/arm9_thumb_ovl_itcm_p5u.c`,
generated by `nnktool recompile-all` at an earlier phase — and then applies
build-time transforms to it.  A prelude fix committed to the tree is therefore
in the shipped binary only if one of those transforms carries it, and nothing
used to check.  Two consecutive phases paid for that:

| phase | the fix was in the tree | the shipped binary | symptom |
|---|---|---|---|
| 5AB | Phase-5X VRAM/palette/OAM read shadow | absent | `untranslated pc=0xe3a03102`, halt `0x020E1B32`, `r4=0xE3A03102` (`blx r4` after reading the vptr back as 0) |
| 5AF | Phase-4G/5AF overlay registry + table | absent (`grep io_ovl_init`: 0 hits) | only the 2 statically-reachable overlay slots were ever measured |

Both were chased as "phantom guest bugs" for hours.  The audit makes the class
loud: the build now **fails** when the runtime TU it is about to compile is
missing a prelude feature the tree defines.

## 2. How a prelude feature can reach (or miss) the binary

Three carriers, all of which the audit covers because it inspects the
**effective prelude** — `nnk_main.c` after the split, plus every `*.inc`
fragment copied next to it, which is exactly what `cc` compiles as the runtime
TU:

1. **`nnktool/src/recompile.rs`** — the canonical `RUNTIME_ALL` /
   `RUNTIME_ALL_MAIN` text.  Emitted into the image at `recompile-all` time,
   so a frozen image predating the change simply does not have it.  Carried
   into a frozen image only by a **splice** (`tools/p5x_runtime_splice.py`,
   `tools/p5ae_runtime_splice.py`, `tools/p5af_ovl_table_splice.py`).
2. **`tools/*.inc`** — `nnk_smc.inc`, `nnk_dma.inc`, `nnk_vramcnt.inc`,
   `nnk_input.inc`, `nnk_boot.inc`.  The image `#include`s them by name and
   `tools/split_dispatch.py` copies them from the tree at build time, so these
   are always current — *provided* the fragment is still copied and still
   #included.
3. **`tools/split_dispatch.py` injections** — ~30 anchored text transforms
   (VRAMCNT width model, 2D shadow, POWCNT1 readback, cart IRQ, VBlank
   producer, IPC responder, card trace, boot firmware, keypad publish, …) that
   upgrade the frozen prelude to current semantics at split time.

A feature can be lost by: a splice being removed/skipped, a `.inc` no longer
copied, an `inject()` anchor drifting so its transform silently no longer
applies, or the image simply predating a change nobody spliced.  The audit sees
all four.

## 3. The mechanism

- **`tools/nnk_prelude_manifest.txt`** — the inventory.  One row per feature:
  `id <TAB> class <TAB> marker <TAB> source <TAB> description`.
  `marker` is a symbol or expression that only that feature introduces
  (`gxd_sh_rd`, `p5f_vc_last`, `io_ovl_pc_report`, …); `source` is the tree
  file that owns it.
- **`tools/prelude_audit.py`** — reads the manifest, builds the effective
  prelude text from a split directory, and classifies every row:

  | class | meaning | audit action |
  |---|---|---|
  | `required` | the shipped binary must contain it | **missing ⇒ exit 1, build fails**; the row's `marker` must also still be in its `source`, else the manifest has rotted |
  | `divergent` | the tree carries it, the frozen image predates it | reported as `image predates the tree`; not enforced (shipping it is a behaviour change that needs its own measured phase).  If it becomes present the audit says `promote to required` |
  | `obsolete` | the image carries it, the tree dropped it | reported as a stale probe; not fatal |

- **`tools/build_split.sh`** — runs the audit after the splices and the split,
  **before** `cc` is invoked, and aborts with `BUILD FAILED: the prelude audit
  rejected …`.  Each splice registers the feature ids it installs
  (`SPLICED_FEATURES+=(…)`) so every build prints one line:

  ```
  prelude: 36/36 features present (spliced: 5x_vram_read_shadow,5x_vram_write_shadow,5ae_vcount_cache,…,5af_overlay_table_dump)
  prelude: image predates the tree (not enforced): 5q_itcm_at_pc, 5ad_quit_path_diag
  prelude: stale in the image (the tree dropped these): 4l_dma_startmode_field, 5r_pred_probe, 5s_dc_probe
  prelude: AUDIT OK
  ```

- **`NNK_PRELUDE_DISABLE_SPLICE=<feature-id>[,<id>]`** — negative control: the
  named splice does not run, so the audit can be observed failing (see §7).

Text-level, not semantic: the audit proves the *feature is present*, not that
it behaves.  Behaviour is still the job of `tools/verify_phase2a.sh`, the
movie-band check and the phase's own measurements.

## 5. The opposite direction: what the frozen image still carries

Two features in the tree are **not** in the image, and three leftovers in the
image are no longer in the tree.  Both lists are printed by every build; none
of them is fatal, and none of them is silent any more.

| feature id | class | marker | note |
|---|---|---|---|
| `5q_itcm_at_pc` | divergent | `itcm_dump_at_pc` | Phase-5Q PC-triggered live ITCM snapshot (the image still carries the 5R/5S probes instead).  Trace-only; promoting it is a probe change, not a guest-behaviour change. |
| `5ad_quit_path_diag` | divergent | `nnk: quit path at step=` | Phase-5AD GX quit-path diagnostics.  Trace-only. |
| `4l_dma_startmode_field` | obsolete | `uint32_t timing = (cnt >> 24) & 3u;` | The image's `io_dma_exec` still decodes DMA StartMode from bits 24..25; the tree reads 27..29.  Harmless **today**: timed/immediate DMA semantics are owned by `tools/nnk_dma.inc`, which carries the correct field — so this is a dead-ish stale line, not a live bug. |
| `5r_pred_probe` | obsolete | `static void pred_probe(uint32_t pc)` | Phase-5R intra-predictor probe, replaced by `itcm_dump_at_pc` in the tree. |
| `5s_dc_probe` | obsolete | `static void dc_probe(uint32_t pc)` | Phase-5S DC-dequant probe, replaced by `itcm_dump_at_pc` in the tree. |

Dropping the three stale blocks would make every shipped build smaller and
would have to go through a fresh image (or three more splices) — out of scope
here; the audit's job is to keep them visible.

## 6. The rule for a future phase

When you add or change a prelude feature (anything in `RUNTIME_ALL` /
`RUNTIME_ALL_MAIN`, a `tools/*.inc` fragment, or a `split_dispatch.py`
injection):

1. **Add a manifest row in the same commit.**  Pick a marker that only your
   feature introduces (a new function/static/expression), not a line that
   other code shares.
2. **Make sure the binary can actually get it.**  If the frozen image predates
   it, either splice it (a `tools/p5XX_*_splice.py` modelled on
   `p5af_ovl_table_splice.py`, copied text only, never a second copy) or
   regenerate the image.  A tree-only fix is a fix the player never sees.
3. **Register the feature ids in the splice block** in `tools/build_split.sh`
   (`SPLICED_FEATURES+=(…)`).  Cargo test 45 fails if a registered id has no
   `required` manifest row, so a splice cannot ship unlisted.
4. **Run the build.**  `prelude: N/N features present` must be N == N.  If the
   audit fails, the message names the feature and its marker — that is the
   build telling you the binary would have shipped stale.
5. **If your change is behaviour-visible and not yet measured**, add it as a
   `divergent` row instead of a `required` one: the audit will keep reporting
   it until its own phase splices it and the row is promoted.
6. **If you delete a prelude feature**, add an `obsolete` row so the leftover
   in the image is reported (cargo test 45 fails if its marker is still in the
   tree, so the row cannot go stale).

## 7. Post-change baseline

- `cargo test`: 45 tests (this phase added
  `phase_5ag_prelude_manifest_is_complete_and_current`).
- Positive build: `NNK_GX=1 NNK_IMAGE_C=work/phase3a/arm9_thumb_ovl_itcm_p5u.c
  bash tools/build_split.sh out/split/arm9_gx` → audit prints `36/36`, the
  build finishes `BUILD OK`.
- Negative control (regression proof): the same command with
  `NNK_PRELUDE_DISABLE_SPLICE=5x_vram_read_shadow` → split still succeeds, then
  ```
  prelude: AUDIT FAILED -- 2 of 36 required features MISSING from the effective prelude
    MISSING  5x_vram_read_shadow          marker 'gxd_sh_rd' not in nnk_main.c or *.inc
    MISSING  5x_vram_write_shadow         marker 'gxd_sh_wr' not in nnk_main.c or *.inc
  BUILD FAILED: the prelude audit rejected …
  ```
  and the process exits 1 before `cc` runs.
- `SKIP_MELONDS=1 bash tools/verify_phase2a.sh` — unchanged; this phase adds no
  guest-visible prelude text of its own (manifest + audit + a cargo test only),
  so the movie band and the crash fix are untouched by construction.

## 8. Limitations, stated honestly

- The check is **textual**.  It proves a feature is present, not that it still
  does what its phase measured.  A marker can be present in dead code.
- It audits the **split** path, which is the shipping path
  (`tools/build_split.sh`).  `NNK_MONO=1` (the mono baseline used only for the
  mono-vs-split equivalence check) compiles the image in place and is not
  audited; the audit relies on `split_dispatch.py` having produced
  `nnk_main.c` + the fragments.
- `divergent` rows are reported, not enforced: shipping them changes
  guest-visible behaviour and needs its own measured phase (band + verifier).
