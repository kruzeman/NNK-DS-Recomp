# CODE_MAP.md — Ni no Kuni DS (B2KJ) ARM9: recovered code map (Phase-2A)

Scope: ARM9 recovery from the decompressed image with `nnktool`
(`disasm` / `decompile` / `recompile-entry` / `recompile-all`).  Everything
here is generated from `work/ghidra_src/arm9.bin` (0x6CB78 bytes, load
@ `0x02000000`, entry `0x02000800`, ARM state at entry).  The stored
`work/arm9.bin` is *not* analyzed — code beyond 0x4000 is still compressed in
it.

Phase-2A supersedes the Phase-1A coverage numbers below; Phase-1A results are
kept because they are the regression baseline (disasm 445/445, entry-only
recovery, first-64 trace).  Reproduce every number with the commands in
[Reproducing](#reproducing).

## Phase-3A — boot past the decompressor (this section supersedes the
Phase-2A "no ground truth beyond 1000 PCs" caveat further down)

Full detail, IO coverage table and reproduction: **[IO_MAP.md](IO_MAP.md)**
and `tools/phase3a_trace_compare.txt`.

**Why the native run used to exhaust its step budget at `0x020009CC`.**  The
run was fed the *decompressed* image (`work/ghidra_src/arm9.bin`), but the
boot stub decompresses the **stored** (compressed) ARM9 blob in place: the
auto-load footer at `0x02000B88` (identical in both images — it sits in the
shared `< 0x4000` boot region) points `data_ptr = 0x02049328` at the
compressed stream, whose 8-byte header at `[dp-8]` carries the cursor bounds
(`work/phase3a/dump_footer.py`):

| image | header @`0x02049320` | r1 src_start | r3 src_end | r2 dest_end |
|---|---|---|---|---|
| stored (`work/arm9.bin`) | `0x0B045328 0x00023850` | `0x02004000` | `0x0204931D` | `0x0206CB78` |
| decompressed | `E3A03006 E58DC000` (game code) | `0x01646322` (below window) | `0x02049245` | `0xE7925328` |

With the decompressed image the descending cursors sweep the whole 24 MiB
flat window (out-of-window reads return 0) — the observed 20 M-step stall.
The stream occupies exactly file offsets `>= 0x4000`, i.e. the region where
stored and decompressed images first diverge (first diff byte `0x4001`), and
the destination only reaches the shared boot region below `0x4000`, so the
decompressor never overwrites its own code.  **The native runtime must
execute against the stored image** (zero-padded to `IMAGE_LEN`;
`work/phase3a/arm9_stored_padded.bin`) — melonDS loads the same bytes.

**Decoder fix required to get there (Phase-3A).**  `ldr/str rd, [rn], #imm`
(post-indexed, P=0) was emitted **without** the base writeback: the decoder
read only the W bit (`decode.rs`, both single-data-transfer and extra
load/store paths), but with P=0 the base is *always* written back (W selects
the unprivileged/T form).  Symptom: the auto-load walker at `0x02000A14`
re-read the same entry forever.  Fixed as `wb = !pre || W`; disassembly text
is unaffected (`ea_text` never printed `!` for post-index forms), so the
445/445 objdump regression still passes.

**Boot depth (honest PC/depth report).**  With the fix, running
`work/phase3a/arm9_all_fixed.c` (generated by the fixed nnktool) on the
stored padded image at the 200 M-step budget:

* the in-place decompressor at `0x02000950..0x020009D0` completes;
* execution proceeds `0x020009D4` (cache flush) -> `0x02000218` (post-
  decompress stub) -> `0x020008A4` `bl 0x020009FC` (**auto-load/init-array
  walker — past `0x020009D0` into real init code**);
* 166 distinct PCs, halt at `0x02000A44` (walker bss zero-fill loop) when
  the step budget expires;
* the decompressor's memory output is **not yet byte-exact vs the reference
  image** (auto-load list at `0x0206CB60` still zero at halt; see
  `work/phase3a/cmp_memdump.py`) — PC trace matches melonDS for the whole
  3 M-line native trace, so the divergence is on the *write/cursor* side of
  the decompressor, not its instruction stream.  Tracked as open work.

**melonDS-vs-native PC trace, extended (Phase-3A).**  `tools/cmp_pc_traces.py`,
report committed in `tools/phase3a_trace_compare.txt`:

| window | melonDS PCs | match | first divergence |
|---|---|---|---|
| acceptance window | 10 000 | **10 000 / 10 000 = 100 %** strict prefix (also window-filtered and post-resync) | none |
| deep capture (5 M melonDS vs 3 M native trace) | 5 000 000 | **3 000 000 / 5 000 000 = 60 %** — native trace file ends at its TRACE_LIMIT; all 3 M captured native PCs match | none inside the native capture |
| deep capture, Thumb image (Phase-3A3, 10 M vs 10 M) | 10 000 000 | **3 633 818 / 10 000 000 = 36.3 %** strict prefix (also window-filtered) | index 3 633 818: melonDS `0x0201C4C0` vs native `0x0201C4AC` |

**Thumb dispatch image (Phase-3A3).**  `work/phase3a/arm9_thumb.c` is the
gap-closed dispatch image: **73 120 cases / 2 020 functions**, Thumb
translation covering the full ARMv5TE Thumb set plus ARM<->Thumb
interworking (`tools/thumb_disasm_check.py` PASS: 86/86 encoding, 85/85 text
vs objdump, 51/51 Thumb instructions, 8/8 interworking in the generated C).
Deep run on the stored image (`sh work/phase3a/run_thumb_deep.sh`, 200 M
steps): the `blx` at `0x0201C178` now enters Thumb at `0x020004A8`, passing
the Phase-3A2 halt point; new halt at **`0x0201C4B8`** (step budget
exhausted; 1032 distinct PCs).  10 M PC trace vs melonDS: **3 633 818 /
10 000 000 = 36.3 %** strict prefix, first divergence at index 3 633 818
(melonDS `0x0201C4C0` vs native `0x0201C4AC`).

**IO model status.**  Nothing is implemented yet; every `0x04000000+`
access is a stub (reads 0, writes dropped).  **Phase-4A supersedes this
paragraph**: the 2026-10-29 boot depth is **step 3,634,038, halt at
`0x020093E4` (`bl 0x01FF845C` — ITCM code execution, the next model gap)**,
the `0x0201C4B8` wait(13,1) loop exits (ARM7 event-chain in RUNTIME_ALL),
3,634,037-trace strict prefix vs melonDS = 100 % of the native trace —
see the Phase-4A section of [IO_MAP.md](IO_MAP.md).  **Phase-4B supersedes
the depth numbers again**: the ITCM/TCM memory model + ITCM dispatch cases
(`NNK_IMAGE_C=work/phase3a/arm9_thumb_itcm.c`, see BUILD.md §9) push the
strict prefix to **3,635,491 / 10,000,000** against the extended-window
(`LO=0x01FF8000`) melonDS capture; the barrier is now the **first ARM9 IRQ
delivery** (melonDS enters the SDK ITCM IRQ stub `0x01FF8000`, native
spins in the `ldrh [0x0206F460]` wait loop until the step budget) — full
stop-report in the Phase-4B section of [IO_MAP.md](IO_MAP.md).  The register set below
was measured with the melonDS IO bus trace
(`tools/melonds-io-trace.patch`, 204 685 accesses / 34 registers over the
first 5 M ARM9 PCs) — and the honest implemented-vs-stubbed table live in
**[IO_MAP.md](IO_MAP.md)**.  Next IO-model target order by observed boot
traffic: DIV/SQRT unit, IPCSync + IPC FIFO with an ARM7 responder stub,
timer 0, DMA, IRQ controller (IME/IE/IF), GE status (GXSTAT), plus the
ITCM window (`0x01FF8000`, where the boot copies and executes code) and the
`0x027E0000` RAM alias.

## Boot path recovered from the entry (Phase-1A, unchanged)

The entry function `0x02000800` is the ARM9 startup stub: it enables the
display power domain (`str` to `0x04000208`, then polls `ldrh [0x04000006]`),
sets up the SVC/IRQ/SYS stacks, clears three RAM regions through
`sub_0200093C` (word-fill loop), flushes caches with three `mcr p15` writes
per line, then tail-jumps (`ldr r1, =0x02000C8C; bx r1` @ `0x02000914`) into
the C runtime start at `0x02000C8C`.

| entry | role | insns | blocks |
|---|---|---|---|
| `0x02000800` | ARM9 startup stub (entry) | 70 | 4 |
| `0x02000A78` | CP15 setup (MPU/caches, MCR p15 sequence) | 46 | 1 |
| `0x0200093C` | word-fill helper (called 3x) | 5 | 2 |
| `0x02000950` | ARM9 LZ-style decompressor (byte-copy loops at `0x02000974..0x020009D0`) | 53 | 10 |
| `0x020009FC` | init-array walker | 30 | 7 |

not walk into, and code Ghidra marked as body that our CFG walk did not reach.

## Jump tables and register-indirect control flow (Phase-2A)

`nnktool decompile` now expands the two ARM switch shapes GCC emits:

* `add pc, pc, rM, lsl #2` — control enters the table at `site+8`; each slot is
  an ARM `b`, so the slots are recovered as real code (bounded by the guarding
  `cmp rM, #N`, else a 16-slot scan cap);
* `ldr pc, [rN, rM, lsl #2]` — table base resolved from the register's
  PC-relative definition (`add rn,pc,#imm` / `ldr rn,=addr` / `mov rn,#imm`),
  each slot word is the absolute target.

Every indirect site is listed with its address in `arm9_decompile.txt`, either
`jump table resolved: …` (42) or `indirect branch (unresolved)` (1963), plus
veneer resolutions (`veneer -> arm 0x…`).  Thumb jump tables are not expanded
(recorded unresolved).

## `recompile-all` — one image-wide PC-dispatch image (Phase-2A)

`nnktool recompile-all <image> <out.c> --seeds <tsv>` emits **one** C program
with a single `switch (pc)` over the whole recovered set:

| metric | value |
|---|---|
| cases (distinct ARM instruction addresses) | 52 395 (565 duplicate addresses de-duplicated) |
| real direct calls / returns | 3032 / 580 |
| runtime-indirect dispatches (`bx`, `ldr pc`, `add pc`, `pop {pc}`) | 2045 |
| Thumb instructions *not* translated | 48 (in 5 functions; fall through to the untranslated-PC halt) |
| generated C | 17.1 MB |

Guest model (unchanged from Phase-1A, widened window): registers `r[16]`,
NZCV flags, single-bank CPSR control byte, flat memory window
`0x02000000..0x03800000` (24 MiB = main RAM + gap + shared WRAM — the regions
melonDS zeroes in `NDS::Reset`; I/O `0x04000000+` is outside the window:
reads return 0, writes dropped), `mcr/mrc p15` no-ops.  Compile:
`cc -O0|-O1|-O2 -o arm9_all arm9_all.c` (-O2 ≈ 15 min on this image, -O1 ≈
6+ min, -O0 ≈ 2 min; the acceptance script uses -O0 with a shortened step
budget for speed — optimization level affects compile/run time only, the
emitted guest semantics are identical).

The run dispatches from `0x02000800` until the first untranslated PC, an
undefined instruction, an unimplemented SWI, interworking to Thumb, or the
step budget; it prints a full per-execution guest-PC trace on stdout and the
summary + HLE log on stderr.

## SWI / BIOS HLE (Phase-2A) — the boot path uses **zero SWIs**

Established three independent ways:

1. `tools/scan_swis_raw.py` (whole image): no ARM `svc` with a
   BIOS-plausible `imm24` falls inside any Ghidra body — the 30 raw candidates
   are data (`0x3FF00000`/`0x3FE00000` doubles, pool words like `0xFFFF0000`
   at `0x02000938`, `0x0202ACA8` …); the 100 halfword `0xDFxx` hits are ARM
   data (96 of them inside ARM bodies, SWI numbers `0x4A/0x4F/0x6D/0x8B…` —
   not BIOS numbers; the plausible-looking cluster at `0x0200006C..0x02000792`
   is in the data area below the entry, which objdump disassembles as garbage
   in *both* ARM and Thumb modes).
2. `tools/scan_swis.py` (per Ghidra function body): 1 function, bogus
   immediates (`0x8F8F90`, `0xA0A0A0` …).
3. The tooling itself: `recompile-all` reports `SWI sites in the recovered set:
   0`, and the native run's HLE log records `hle_hits=0`.

The HLE dispatcher is nevertheless real and reference-faithful:

* number convention from melonDS's FreeBIOS (`freebios/src/bios_common.s`,
  `swi_handler: ldrb r12, [lr, #-2]` → **number = imm24 bits 16..23**, numbers
  `>= 0x20` map to the invalid slot); a GBA-style low byte is logged as `lo=`
  but never dispatched on, so an encoding difference stays visible;
* every hit is logged *before* semantics run:
  `hle swi imm24=… num=… lo=… at=… r0=… r1=… r2=… r3=…`;
* implemented with FreeBIOS-exact semantics: `0x09` Div (signed quotient,
  magnitude remainder, `r3 = |quotient|`), `0x0B` CpuSet (`r2` bits 0..20 count,
  bit26 = word, bit24 = fill), `0x0C` CpuFastSet (word only, bit24 = fill, count
  as-is), `0x0D` Sqrt (integer square root);
* anything else **halts** with `SWI not implemented in the Phase-2A HLE` — no
  SWI ever looks successful without its effects.

## Ground truth: melonDS ARM9 PC trace vs native (Phase-2A headline)

Ground truth comes from the local melonDS build
(`/home/hermes/tools/melonDS`, interpreter, FreeBIOS, real ROM):
`tools/melonds-arm9-ptrace.patch` adds an env-gated ARM9 trace hook
(`MELONDS_ARM9TRACE_PATH/_N/_LO/_HI/_EXIT`) in `src/ARM.cpp` — kept outside
`gxrender/`, built into a separate `build-ptrace/` so gxrender's
`build/melonDS` is untouched.  The hook logs every ARM9 instruction PC in
`0x02000000..0x02400000` (`R[15]-8` in ARM state, `R[15]-4` in Thumb) and
exits after N PCs.

| metric | value |
|---|---|
| melonDS guest PCs captured | 1000 (from `0x02000800`) |
| SWIs in the melonDS trace | 0 (matches the static result) |
| **strict common prefix, melonDS vs native** | **1000 / 1000 = 100 %** |
| window-filtered prefix | 1000 / 1000 |
| in-order matched after resync | 1000 / 1000 |
| first divergence | none inside the window |

Beyond the 1000-PC window there is **no ground truth in this run**: the native
run keeps executing and ends with `halt=step budget exhausted` at
`halt_pc=0x020009CC` (the ARM9 decompressor's outer loop, `0x020009C8..0x020009D0`;
20 M steps, 125 distinct PCs in the acceptance run, 160 at the default 200 M
budget).  That region past 1000 PCs is **unverified**, not claimed as
matching — the plausible causes are exactly the documented model gaps (I/O
reads returning 0, no IRQ/timing model, RAM outside the loaded image reading
as 0).  Raise `MELONDS_ARM9TRACE_N` to extend the ground truth window.

## Disassembler accuracy (regression, Phase-1A baseline still PASS)

`nnktool disasm` vs `arm-none-eabi-objdump` on four ranges, **445/445**
encoding and text matches: `0x02000800..0x02000B00` ARM 192/192,

## Known limitations

1. Thumb is recovered but not translated: 5 Thumb functions / 48 instructions
   in the seeded set are reported, not emitted; dispatching into them halts.
2. Single-bank register model: `msr cpsr_c` mode switches do not bank r8-r14.
3. Flat memory window `0x02000000..0x03800000`, all zero outside the image —
   matches melonDS's reset state for RAM, but **I/O reads return 0** and I/O
   writes are dropped (no register semantics, no IRQ/timing model).  Any boot
   code polling a hardware flag that is non-zero in melonDS will diverge there.
4. No interrupt model: an IRQ-wait loop would run to the step budget instead of
   being woken.
5. 1963 register-indirect sites remain unresolved (recorded with addresses);
   only the two jump-table shapes above are expanded.
6. SWI HLE covers `0x09/0x0B/0x0C/0x0D`; any other number halts (the boot path
   hits none — see above).
7. Literal pools are only excluded from code by control flow (0 undefined-
   instruction terminations in the recovered sets).

## Reproducing

All commands run from the repository root; outputs land in `work/` (never
committed).

```sh
cargo build --release --manifest-path nnktool/Cargo.toml

# everything, end to end (A = 445/445 regression, B/C = recovery + coverage,
# D = recompile-all + run, E = melonDS ground truth, F = trace comparison)
sh tools/verify_phase2a.sh                 # ~5-20 min (cc -O1 dominates)

# 1) disassembler vs objdump (4 sampled ranges)
sh tools/verify_phase1a.sh                 # sections A-D, PASS

# 2) seeded recovery from ALL Ghidra entries
nnktool/target/release/nnktool decompile work/ghidra_src/arm9.bin work/phase2a \
  --base 0x02000000 --entry 0x02000800 --seeds work/ghidra_arm9_functions.tsv

# 3) cross-checks
python3 tools/crosscheck_ghidra.py work/phase2a/arm9_functions.tsv work/ghidra_arm9_functions.tsv
python3 tools/coverage_ghidra.py work/phase2a/arm9_decompile.txt work/ghidra_arm9_functions.tsv

# 4) recompile the whole recovered set -> C -> cc -> run (trace + HLE log)
nnktool/target/release/nnktool recompile-all work/ghidra_src/arm9.bin \
  work/phase2a/arm9_all.c --base 0x02000000 --entry 0x02000800 \
  --seeds work/ghidra_arm9_functions.tsv
cc -O1 -o work/phase2a/arm9_all work/phase2a/arm9_all.c
work/phase2a/arm9_all work/phase2a/arm9_all.image.bin \
  > work/phase2a/native_trace.txt 2> work/phase2a/native_hle.txt
grep -c '^hle swi' work/phase2a/native_hle.txt     # 0 — no SWI in the boot path

# 5) ground truth: melonDS ARM9 PC trace (patch + separate build)
#    tools/melonds-arm9-ptrace.patch against /home/hermes/tools/melonDS src/ARM.cpp,
#    cmake --build build-ptrace, then:
SCRATCH=~/.hermes/profiles/coder/cache/scratch
MELONDS_ARM9TRACE_PATH=$SCRATCH/melonds_arm9_trace.txt MELONDS_ARM9TRACE_N=1000 \
  xvfb-run -a /home/hermes/tools/melonDS/build-ptrace/melonDS "Ni No Kuni.nds"

# 6) compare (strict prefix = 1000/1000)
python3 tools/cmp_pc_traces.py $SCRATCH/melonds_arm9_trace.txt work/phase2a/native_trace.txt
```
