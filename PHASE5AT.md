# Phase-5AT — the wrong MODE, corrected by an audited override: both reproducers pass 0x02062C48

Follows Phase-5AS (merged as `8408e2d`).  Build:
`NNK_GX=1 NNK_IMAGE_C=work/phase3a/arm9_thumb_ovl_itcm_p5u.c bash tools/build_split.sh <out>`
(prelude audit green, `cargo test`: **57 passed**).

## 1. Result

`0x02062C48` was never a state-carrier problem: it was a **mode-table** row.
Phase-5AS established that `0x02062C44` is Thumb — ov17's Thumb function
`0x020FEB94` calls it with `bl 0x02062C44` at `0x020FEBB2` (LR = `0x020FEBB7`,
odd = Thumb caller) and the bytes are `b510 1c04` = `push {r4,lr}` /
`adds r4,r0,#0` — but the Ghidra seed row carries `insn_len = -1` (unknown),
which `load_seeds` defaults to ARM, so the frozen image emitted the ARM
`cdpne` reading and trapped at `0x02062C48` on `undefined instruction
0xF94AF000`.

**Both reproducers now run past it, with the carrier OFF, to their step budget:**

| reproducer | master `83f38f0` | this build |
|---|---|---|
| cold boot, operator session | `halt=undefined instruction 0xF94AF000` at step 508,793,671 | `done steps=700000001` (budget), 1,256 frames, 13/13 input events applied, distinct_pcs 25,484 |
| savestate (`NNK_SAVESTATE_IGNORE_BUILD=1`) | same halt at ~626,972,668 | `done steps=640000001` (budget), 1,149 frames, distinct_pcs 24,906 |

New frontier (§4): not a decode error — both runs settle in **wait loops**.

## 2. The supported override (task item 1)

`tools/nnk_mode_overrides.txt` (committed) is the authority:

```
<address> <arm|thumb> <reason>
```

`0x02062C44 thumb` is its first row, with the caller measurement as the reason.
The grammar is enforced by `nnktool/src/modeov.rs`: bit0 set, an unknown mode,
a duplicate address or a row **without a reason** are errors, so an override
cannot be added silently.

`nnktool` consumes it (`--mode-overrides <file>` on `recompile-all`,
`decompile` and the new `recompile-cases`), and `recover::set_mode_overrides`
makes the table authoritative at the single point where a `FuncKey` is created
— so it applies to seeds **and** to every function reached by a direct call,
transitively, not just to the row it names.

## 3. How the correction reaches the shipped image (task item 2)

**Splice, generated by the recompiler** (the second option in the task; the
frozen image is a shared, heavily-measured artifact and regenerating it would
re-derive every function):

* `nnktool recompile-cases <image> <out.c> --base --entry --mode [--mode-overrides]`
  emits one function's dispatch cases with the SAME per-instruction emitter and
  `case_string` that `recompile-all` uses.  Nothing is hand-written.
* `tools/p5at_mode_splice.py <in.c> <out.c>` asks it for every row of the
  override file, drops the frozen image's cases inside the corrected body's
  range, inserts the generated ones, writes the audit marker as the file's first
  line, and reports direct-call targets the image does not translate.
* `tools/build_split.sh` runs it, marker-gated, after the 5AP splice:
  `SPLICED_FEATURES+=(5at_mode_override)`, and
  `NNK_PRELUDE_DISABLE_SPLICE=5at_mode_override` is the negative control.
  Row `5at_mode_override required "Phase-5AT mode-override splice applied"`
  in `tools/nnk_prelude_manifest.txt` makes the prelude audit fail the build if
  the splice is dropped.

Measured splice output:

```

      inserted 11 case(s) [0x02062C44 0x02062C46 0x02062C48 0x02062C4C 0x02062C4E
                           0x02062C50 0x02062C54 0x02062C56 0x02062C58 0x02062C5C 0x02062C5E]

         0x02062EE0 0x020DEDF8 0x020FB168
```

(The three callees are still executed — the ROM-derived SMC generation-0 live
decoder serves them from RAM; that is why the run does not halt at 0x02062EE0.
They are recovery holes of the *compiled* set, not wrong modes.)

### Mode-table diff (before/after)

Recovery of `work/arm9_dec.bin` with the same seeds, with and without the
override (`nnktool decompile … --seeds work/phase3a/seeds_phase3a3.tsv`):

```
2111c2111,2112
< 0x02062C44  arm    2 insns   8 bytes  1 undef
> 0x02062C44  thumb 11 insns  28 bytes  3 calls  0 undef
> 0x02062EE0  thumb 49 insns 100 bytes  1 call   5 unresolved indirects
```

**Exactly one row changes mode.**  The one *added* row is the consequence of
walking the body correctly: the ARM 2-instruction reading never reached
`0x02062EE0`, the Thumb body calls it.  No other function moves — which is why
the file needs one row and not a blanket rule.

## 5. Carrier status (task item 4)

`NNK_STATE_CARRIER` stays **opt-in and experimental**; documented in
`SAVESTATES.md` §5b.  Its cold-boot divergence (step 18,395,574, near
`0x027FF800`) is untouched — it is a defect of the carrier, not of the mode
table, and Phase-5AT removes the reason the carrier was needed at
`0x02062C48`, so there is no case for flipping the default now.
